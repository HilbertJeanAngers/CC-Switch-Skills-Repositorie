# Notion Course Notes（诊断驱动版）

## 一、架构约定：大脑与手（必读，不要越界）

- **`notion-notes` MCP = 大脑**：唯一持有 Notion 访问能力（令牌、API、块构造）。**所有 Notion 读写必须调用 MCP 工具**；不要自己写脚本、不要用 curl 直连 Notion API，不要在本目录重建脚本。
- **本 skill = 手 + 分析器**：负责诊断、定方案、决定内容写法、组合调用 MCP。不实现任何 API 访问。
- **风格唯一来源**：MCP 的 `notion_get_style_guide` 返回的 `STYLE.md`。本目录不存放风格文件，不要凭记忆猜规则。

**前置条件**：`notion-notes` MCP 已连接（能调用 `notion_search`）。若当前会话搜不到这些工具，提示用户在 WorkBuddy 设置里信任/启用该 MCP 并重启会话——**不要退化成脚本方案**。

## 二、MCP 工具速查（大脑提供的能力）

| 工具 | 用途 | 何时用 |
|---|---|---|
| `notion_search(query, limit)` | 定位目标页面 | 用户只给了页面名关键词时 |
| `notion_read_page(page_ref, max_blocks)` | 读块结构（含层级、折叠标记） | 诊断必用；设大一些 |
| `notion_analyze_images(page_ref)` | 找出缺文字的裸图，返回编号+block_id+section | 诊断"漏洞"维度必用 |
| `notion_download_image(url, name)` | 下载图片到本地（附放大版）供看图识别 | 识别图中知识点时 |
| `notion_insert_caption(page_ref, image_block_id, text, block_type)` | 在图前插注释，内置防重复 | 逐张补注释 |
| `notion_append_blocks(page_ref, blocks)` | 追加任意块（每项 ≤100 项） | 只用于新增内容，**不用于整理** |
| `notion_delete_blocks(ids, dry_run)` | 原地归档块，可批量 | 删除空块/冗余块（可 `notion_restore_blocks` 撤销） |
| `notion_update_block(id, patch)` | 原地改块文字/折叠状态 | 把标题设为可折叠、改错字 |
| `notion_nest_blocks(heading_id, ids)` | 把块复制进折叠标题并删原块 | 原地折叠嵌套（先复制后删，失败回滚） |
| `notion_move_blocks(ids, after_id)` | 原地重排块顺序 | 重排（先复制后删） |
| `notion_backup_page(page_ref, output_path)` | 备份页面完整 JSON | **任何改动前必做** |
| `notion_archive_page(page_ids, remember)` | 移入 Notion 回收站（可恢复） | 暂时移出视线 |
| `notion_restore_page(page_ids, from_archive_log)` | 撤销归档 | 恢复被归档页面 |
| `notion_get_style_guide()` | 取权威风格与折叠规则 | 诊断必用（标准基线） |

`page_ref` 可传页面标题关键词或页面 ID；多个匹配时 MCP 会返回候选，让用户选或改用 ID。

## 三、核心工作模式：四阶段（默认，任何整理请求都走）

**铁律：先诊断，后动手。** 除非用户明确说"直接做/别问了"，否则不得跳过阶段 1→2 直接改。用户的关键词只决定**诊断重点**，不决定直接套哪条流水线。

### 阶段 0 · 锁定范围

1. 用 `notion_search` 定位页面；多匹配让用户选或改用 ID。
2. 记住用户这次的**显式诉求**（如"补注释""折叠""检查漏洞"）——它是诊断重点，但不是全部。
3. 判断诊断深度：默认**四维度全查**；页面很大且用户只要改一处时，可只深查相关维度，但仍要快速扫一遍其余三项。

### 阶段 1 · 全面诊断（自动执行，四个维度）

诊断前先并行取两份基线：`notion_get_style_guide()`（标准）+ `notion_read_page(page_ref, max_blocks=大)`（现状，递归 `has_children`）。页面含图片时再调 `notion_analyze_images(page_ref)`。

逐维度检查，**每条发现必须有证据**（block_id 或原文片段），不许空泛下结论：

#### 维度 1：内容漏洞与完整性
- 标题下面没有内容 / 只有一两句就断掉
- 有孤儿块：段落没有所属章节，或出现在不合逻辑的位置
- 空块、纯标点块、重复出现的同一句/同一图
- 裸图（有图片但前后无文字说明）→ 用 `notion_analyze_images` 的 `bare=true`
- 表格/代码块残缺、链接失效的迹象
- 章节顺序错乱（如"进阶"出现在"基础"之前）

#### 维度 2：内容完善度（靠 agent 的领域知识判断）
- 术语出现但**没有解释**（尤其英文缩写、专业名词首次出现）
- 概念只给结论没给例子，或只给例子没归纳概念
- 同一主题的**关键项缺失**（如讲熔炉只提转炉、漏了电弧炉/精炼炉）
- 中英术语不一致、同一个概念用了两种叫法
- 有明显笔误、错别字、重复词
- **注意**：内容补充要克制，按 STYLE.md"补充适度"来；不为了显得丰富而堆砌。

#### 维度 3：标准对齐（严格对照 `notion_get_style_guide()`）
- 一级标题是否**全部** `is_toggleable: true`，内容是否都在 children 里
- 二级/三级标题是否按内容长度合理折叠（长则折、短则平铺，不为折叠而折叠）
- 折叠标题是否夹带"（点击展开）"等废话后缀
- 图片注释的块类型 / 前缀 / 后缀是否符合 STYLE.md 机器可读配置
- 注释是否贴在对应图片**正前方**、一图一条（或多图共用一条）
- 一段内容是否过长到该拆分 / 过碎到该合并

#### 维度 4：格式与布局
- 需要嵌套但未嵌套的章节；嵌套层级过深（>3 层）
- 空段落、连续多个 divider、无意义的占位符
- 列表项编号断裂、bullet 与 paragraph 混用
- 标题层级跳跃（h1 直接到 h3）

#### 诊断报告模板（分析完先写成这个结构）

```
## 🔍 笔记体检报告：<页面名>
基线：风格 = <STYLE.md 来源> ｜ 块总数 = <N> ｜ 图片 = <M> 张（裸图 <K>）

### 发现的问题（按优先级）
| # | 维度 | 位置 | 现象（带证据） | 建议动作 | 优先级 | 风险 |
|---|------|------|----------------|----------|--------|------|
| 1 | 标准对齐 | block xxx | h1「furnace」未折叠 | 设为可折叠并嵌套 4 条术语 | P0 | 安全·不改语义 |
| 2 | 内容漏洞 | block xxx | 空段落 | 归档删除 | P2 | 安全·不改语义 |
| 3 | 内容完善 | 章节 yyy | 「BOF」首次出现无解释 | 补一句中文释义 | P1 | 需确认·会增字 |

优先级：P0 结构/数据完整性或硬性风格违规 · P1 内容缺失或标准偏差 · P2 优化项
风险：「安全」= 纯结构/排版调整；「需确认」= 会新增或删改文字（必须用户点头）

### 结论
<一句话概括：这页主要问题是什么，建议先做哪几项>
```

**如果诊断发现零问题**，直接说明"体检通过，无需改动"，不要为了干活而制造改动。

### 阶段 2 · 生成方案 + 确认关卡

1. 把诊断报告按优先级排成方案：先 P0 结构问题，再 P1 内容问题，最后 P2 优化。
2. **展示报告 + 方案给用户**，并说明哪些是"安全的结构调整"、哪些是"会改文字的内容补充"。
3. 等用户确认/调整范围后再执行。用户说"按你说的办""全做"即视为确认全部；用户可只挑某几项。
4. 用户若说"直接做、不用问"，可跳过等待，但仍要**先输出诊断报告**再执行——分析不能省。

### 阶段 3 · 执行（从手段库组合，不是套单一流水线）

按方案逐项执行，一次只做一类，做完一类复验一类。手段见下方第四节：
- 裸图 → 手段 A
- 内容缺失/笔误/完善 → 手段 B
- 折叠/嵌套/重排/删空块 → 手段 C
- **任何改动前先 `notion_backup_page`**（一次任务备份一次即可）。

### 阶段 4 · 复验（逐条对照诊断报告）

1. `notion_read_page` 重读，逐条核对诊断报告里的每个问题是否已解决。
2. 统计块总数与备份对比：纯整理类改动应**数量守恒或只少空块**；内容补充类应**只多不少**，并说明新增了哪几块。
3. 确认折叠标记、嵌套层级、注释位置正确。
4. 告诉用户：改了哪几项、备份路径、怎么回滚。
5. **不要**在复验通过前宣称完成。

## 四、执行手段库（阶段 3 按需组合，不再是入口路由器）

### 手段 A：图片补注释

1. `notion_analyze_images(page_ref)` → 记下裸图的 `n`、`image_block_id`、`section`。
2. `notion_download_image(url, name)` 拿本地路径 → 看图 → 记下"编号 → 知识点短语"。短语照图中标题/核心概念命名，简短不加句号；字看不清用返回的 `large_path`。
3. 按 `notion_get_style_guide()` 的块类型/前缀/后缀写注释；用户本次有特殊要求可临时覆盖，不改配置。
4. `notion_insert_caption(page_ref, image_block_id, text, block_type)` 逐张插入（已有相同文字会自动跳过；`unsupported` 块保持原样）。
5. 复验：再跑 `notion_analyze_images` 确认裸图消除、顺序正确。

### 手段 B：内容补齐 / 修正

1. 读现状 `notion_read_page`，确认插入点（哪个章节、哪个块之后）。
2. 按 简介 / 安装或准备 / 核心概念速查 / 少量精选示例 / 学习路线 组织（按领域裁剪，不必凑齐）。**补充适度**：示例 1~2 段够说明问题即可，不要为每个小点堆一大段代码。
3. `notion_append_blocks(page_ref, blocks)` 写入，blocks 为 JSON 数组字符串，每项如 `{"type":"h1","text":"一、简介","toggleable":true}`。支持 `text/paragraph`、`h1/h2/h3`、`code`、`quote`、`bullet`、`number`、`callout`、`divider`、`toggle`。**一次最多 100 块**，超量分批。
4. 局部修正用 `notion_update_block`；笔误只改文字，不动结构。
5. 复验：读回确认新增内容位置正确、折叠标记符合规则。

### 手段 C：布局整理（原地）

**铁律：在哪一页就在哪一页改，绝不跨页搬运。** 子页面（child_page）的内容属于子页，必须在子页内整理；不要提取到父页做"整理版导航/摘要"——用户明确否决过这种做法。父页只整理父页自己的块。

1. `notion_read_page(page_ref, max_blocks)` 设大一些，注意递归进 `has_children`（表格、已有折叠标题都有子块）。
2. `notion_update_block(block_id, '{"heading_1":{"is_toggleable":true}}')` 把标题设为可折叠。
3. `notion_nest_blocks(heading_id, "子块ID,子块ID,...")` 把章节内容**复制进标题 children 并校验成功后自动删除原块**（先复制后删，永不先删；失败自动回滚副本）。一次调用处理一个章节（标题到下一同级标题之间的块）。
4. `notion_delete_blocks(ids, dry_run)` 原地归档空块/冗余块（可 `notion_restore_blocks` 撤销）；`notion_move_blocks(ids, after_id)` 原地重排（先复制后删）。
5. `dry_run` 用于验证嵌套/删除范围，**先 dry-run 再实做**。
6. **注意**：`notion_append_blocks` 只用于新增内容，**不要用它做布局整理**。`child_page` 类块不可复制嵌套，遇到时跳过、保持原样。二/三级短标题不要为了折叠而折叠。

## 五、折叠规则（判断依据，细节以 MCP 的 STYLE.md 为准）

- **一级标题（heading_1）必须折叠**：`is_toggleable: true`，内容放 `children`，不管长短。
- **二级/三级标题按长度适当处理**：内容长（多段/多代码/多图）做可折叠；短的直接平铺，不为折叠而折叠。
- **折叠标题只写知识点名**，禁止"（点击展开）""（点开查看）"这类后缀。

## 六、风格修改与临时覆盖

- 用户说"以后注释风格改成 XXX"→ 编辑 **MCP 目录下的 `STYLE.md`**（`notion_get_style_guide` 返回的 `source` 路径），一次修改全局生效；**不要改本 skill 目录**。
- 用户说"这次用 XX 风格"→ 仅本次调用时覆盖，不改文件。

## 七、恢复与安全约定

- **撤销归档**：`notion_restore_page(from_archive_log=true)`，或传逗号分隔的页面 ID。
- **内容有损回滚**：用 `notion_backup_page` 产出的 JSON 对照，通过 `notion_append_blocks` 手工重建。
- 令牌由 MCP 统一管理，本 skill 不接触、不落盘。
- 改动前必备份；临时图片由大脑下载到系统临时目录，用完可清理。
- 归档优先于永久删除；不擅自永久删页面。
- **诊断发现的问题若超出本次请求范围，只报告不强改**——尊重用户的选择权。

## 八、详细参考

- 风格与折叠规则：`notion_get_style_guide()`（唯一权威源，MCP 目录 `STYLE.md`）
- Notion API 要点与踩坑：由 MCP 内部处理；出现异常时看工具返回的错误信息，不要自行绕过 MCP。
